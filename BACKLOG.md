# Orchestrator — Feature Backlog

Tracker for proposed work that hasn't yet been promoted into `PLAN.md`. When an
item is scoped + accepted, move it into `PLAN.md` and mark it `[x] promoted`
here (don't delete — kept for provenance).

Two sources feed this list:

1. **Skill-driven findings** — output from `engineering-skills:senior-architect`
   and `engineering-skills:tech-stack-evaluator` run against this repo on
   2026-05-20. Anchored to actual measurements; rationale is empirical.
2. **Pattern-matched ideas** — generated by reading the
   `alirezarezvani/claude-skills` repo (the marketplace's default source) for
   what *kinds* of features other teams have built. Rationale is "someone else
   shipped this, looks applicable."

Skill-driven items are higher-confidence (they point at measured pain). Pattern
items are lower-confidence (they're inspiration, not diagnosis).

## Status legend

- `[ ]` idea — captured, not yet scoped
- `[~]` scoped — has a concrete plan, ready to start
- `[>]` building — work in progress on a branch
- `[x]` promoted — moved into `PLAN.md` milestones / shipped
- `[-]` rejected — explicitly declined (keep with a one-line reason)

## Skill-driven findings (2026-05-20)

Concrete measurements from `project_architect.py` + `dependency_analyzer.py`
runs, plus `tech-stack-evaluator` decision-framework application:

- Project pattern detected as **Unstructured** (0% confidence — no
  layered/hexagonal/MVC convention)
- **8 files over the 500-line threshold**, full list in each item below
- **0 circular dependencies**, coupling score **0/100 (low — good)**
- 8 prod deps, 18 dev deps (lean)
- Total: 46,957 lines across 170 files

### S1. `[ ]` Marketplace module split

**Measurement:** `src/main/marketplace.ts` is 1,735 lines — the largest file in
the repo, grew there during v0.8/v0.9.

**Rationale:** The Code Review 2026-05-18 explicitly deferred L1 file splits.
The data now says marketplace specifically has outgrown that decision while
other big files have stayed proportionate.

**Sketch:** split into source-registry / subscription-state / loadout-resolver
/ telemetry-attribution modules. Memory note `code_review_2026_05_18_decisions`
captures the original deferral context.

### S2. `[ ]` IPC split + runtime schema validation

**Measurement:** `src/main/ipc.ts` (1,295) + `src/shared/ipc.ts` (800) =
**~2,100 lines of contract surface with zero runtime validation**.

**Rationale:** TS types exist on both sides but nothing enforces them at
runtime — a renderer→main shape drift would surface as a confusing TypeError
deep in a handler rather than a loud boundary error.

**Sketch:** (a) split `src/main/ipc.ts` by domain (auth / agents / marketplace
/ mcp / spend / runs); (b) add `zod` (or `valibot`) schemas on each IPC channel
in `src/shared/ipc.ts`; (c) wrap handlers in a `validated()` helper that
rejects with a typed error on mismatch.

### S3. `[ ]` Adopt an explicit layer convention

**Measurement:** `project_architect.py` returned "Unstructured (0%
confidence)". Top-level `src/`, `out/`, `docs/` all classified as `unknown`.

**Rationale:** Not a refactor sprint — a `LAYERS.md` + a lightweight ESLint
rule pinning `src/main/<domain>/` modules. Prevents the marketplace.ts
situation from recurring elsewhere as the codebase grows.

**Sketch:** define 4-6 named layers (e.g., `cli-adapter`, `domain`,
`persistence`, `ipc`, `renderer`); document the dependency direction rule;
enforce via `eslint-plugin-boundaries` or similar.

### S4. `[ ]` better-sqlite3 revisit

**Measurement:** v0.9 added `skill_fire_counts` + per-turn modelUsage rows;
write frequency is climbing.

**Rationale:** Locked decision picked sql.js because no MSVC toolchain was
available locally. `better-sqlite3` ships prebuilt binaries via
`prebuild-install` so the original blocker may have evaporated. The
framework's database selection workflow points back at it for `<1M records,
write-heavy single region`.

**Sketch:** spike-only first — measure current write latency in a 24h
real-usage trace, then decide. Don't ship the swap until the data justifies
it.

### S5. `[ ]` Crash + perf telemetry

**Measurement:** Stack has zero observability — `tech-stack-evaluator`
flagged this as a tier gap.

**Rationale:** Releases ship every couple of days. When a release crashes on
someone else's machine (or your own renderer process), there's no signal at
all — you find out only if a user notices and reports.

**Sketch:** opt-in only (single-user app, privacy matters). Local structured
log to `userData/crashes/` on `uncaughtException` + renderer error boundary;
optional manual upload via a "Send crash report" button. Pairs with the
hypothetical Spend optimizer panel (P3) — both want the same telemetry.

### S6. `[ ]` Self-hosted update channel fallback

**Measurement:** `update-electron-app` polls `update.electronjs.org` every
10 min — single-point-of-failure dep flagged by the framework's
dependency-risk axis.

**Rationale:** `update.electronjs.org` is public-repo-only. If the repo ever
flips back to private (or moves off GitHub), auto-update breaks silently and
users sit on stale versions indefinitely.

**Sketch:** add a second-channel fallback using `electron-updater` against a
self-hosted manifest (S3 + signed JSON). Try primary, fall back to secondary
on failure. Doesn't replace the current channel — it's a hedge.

### S7. `[ ]` agents/runner.ts split

**Measurement:** `src/main/agents/runner.ts` is 1,190 lines;
`src/main/director/runner.ts` is another 614.

**Rationale:** Commit `e5ab6a7` already started carving with the `buildQuery`
helper. Natural follow-up.

**Sketch:** split into event-classifier / budget-enforcer / fork-redirect /
persistence-hooks. The hardening pass already added `agent-lock.ts` —
follow that pattern (small, focused modules around `runner.ts`).

### S8. `[ ]` End-to-end test harness

**Measurement:** No e2e harness detected; `tech-stack-evaluator` flagged this
against the cadence (release every ~2 days).

**Rationale:** The v0.4.0 ASAR-fuses regression (silent install failure) and
the v0.5.x codex Fork issues would have been caught by a "installer launches
+ renderer renders" smoke test in CI.

**Sketch:** Playwright-on-Electron with one smoke scenario — launch packaged
installer in a clean container, verify renderer mounts, verify Director chat
accepts input. Wire into `release.yml` as a gate before tag publication.

## Pattern-matched ideas (from earlier brainstorm)

These came from reading the `alirezarezvani/claude-skills` repo structure for
feature inspiration — not from measuring this codebase. Lower confidence,
higher creativity.

### Product features

- **P1.** `[ ]` **Workflow Templates** — fills the existing `Templates` rail
  placeholder. Library of named Director plans (Ship a feature / TDD bug fix
  / Security audit / Onboarding) loadable into the composer. Cornerstone for
  P11 + P17 below.

- **P2.** `[ ]` **Codebase Onboarding preset** — one-shot researcher on first
  workspace open; produces `WORKSPACE.md`; Director auto-receives it as
  context. Banner offer + "Re-run onboarding" in workspace-pill dropdown.

- **P3.** `[ ]` **Spend Optimizer Panel** — rule-based recommendations on
  Spend screen using existing `modelUsage` data. Role-share / cache-hit /
  idle-skill / wallclock-outlier rules. No LLM; cheap.

- **P4.** `[ ]` **Per-project per-role prompt overrides** — extend Tools
  screen with a Prompt tab; diff against `roles.ts` defaults; last-10
  edit history; `resolveRolePrompt(role, projectId)` in runner.

- **P5.** `[ ]` **Ship Gate on plan acceptance** — checkbox on PlanCard
  appends qa + security rows that must pass before Director receives
  completion handoff. Hardcoded prompts; per-project persisted toggle.

- **P6.** `[ ]` **Self-improving loadouts** — use v0.9 `skill_fire_counts`
  to nudge: idle-skill unsubscribe / hot-skill promotion / loadout-drift
  reset. Surface as "Skill insights" card on Marketplace screen, not
  intrusive popups.

- **P7.** `[ ]` **Marketplace source security audit** — static heuristic
  audit on new GitHub source subscription (network calls, fs writes outside
  workspace, credential-store access). Red/yellow/green per skill before
  user confirms. Default source skips the check.

- **P8.** `[ ]` **Focused-fix quick spawn** — skip Director for the
  single-file-bugfix case. File picker + 3-line task + budget override
  → one coder agent with file pinned and strict allow-list.

- **P9.** `[ ]` **MCP server builder wizard** — scaffold a new MCP server
  in workspace (TS or Python), auto-register in `.mcp.json`. Pairs with
  v0.8's MCP support.

- **P10.** `[ ]` **Playwright QA role variant** — subtype dropdown at qa
  spawn time; auto-subscribes `playwright-pro` skill; adds Playwright to
  shell allow-list; KPI strip gains "Tests: N pass / M fail" tile.

### Smaller follow-ups (mostly depend on P1)

- **P11.** `[ ]` **Save run as Runbook** — button on Runs screen turns

- **P12.** `[ ]` **Changelog generator from session** — button on Runs;

- **P13.** `[ ]` **Per-agent worktree re-spike** — re-investigate the M2

- **P15.** `[ ]` **PRD mode (Director third mode)** — alongside auto /

- **P16.** `[ ]` **Session recap generator** — button on Runs; one-shot

- **P17.** `[ ]` **Dependency auditor preset for security role** —

## Cross-references and overlaps

- **S2 ↔ P4**: both touch the IPC + per-project overrides surface. Do S2
  (split + zod) first — it's a clean foundation; then P4 adds one more
  IPC channel to the freshly-split layer instead of widening the monolith.
- **S5 ↔ P3**: the Spend optimizer's recommendations are better with the
  crash/perf telemetry from S5. Ship S5 first, P3 lights up on the same
  data pipeline.
- **S6 ↔ public-repo decision**: only matters if the repo flips back to
  private. Lower priority while it stays public.
- **P1 → P11 / P17**: P1 is the cornerstone — both P11 and P17 use the
  Templates infrastructure as their persistence layer.

## Sequencing suggestion

If picking the next 3 slices off this list, the data favours:

1. **S1** — marketplace.ts split (biggest measured pain, clear scope)
2. **P1** — Workflow Templates (unblocks 2 follow-ups; visible UI win)
3. **S2** — IPC split + zod (enables every future per-domain feature to

regresses on something the cadence is making hard to catch.

## How to update this file

- When you scope an item, change `[ ]` → `[~]` and add a sketch link or PR.
- When work starts, change to `[>]` and link the branch.
- When the item ships or is promoted into `PLAN.md`, change to `[x]` and add
  a one-line "shipped as part of vX.Y.Z" note.
- Reject with `[-]` + a one-line reason if you decide an item isn't worth it.
  Don't delete — the rejection record is more valuable than the missing
  entry, because the next ideation pass will re-propose it otherwise.
